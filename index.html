// self-initiated · migration snapshot

Parallel Proxmox platform alongside the VMware estate

Nobody assigned this one. I costed the commercial virtualization licensing, wrote it up as a Kaizen and MUDA elimination proposal, and once it was approved I built a Proxmox VE platform running alongside the existing VMware estate. Production services were rebuilt natively on the new platform rather than converted from the old VMs. That took longer, but it meant nothing carried over from the previous configuration. The production estate now runs 24 LXC containers and 12 Linux and Windows VMs across 7 bare-metal hosts for around 700 staff. LXC is the default for Linux web workloads because it is lighter; full VMs stay where a workload needs stronger isolation or has platform specific dependencies.

Proxmox Provisioning Automation

~4h → ~17m

Problem: Every VM and LXC was built by hand. It was slow and repetitive, and the configuration drift that came with it had already caused incidents we should not have been having.

What I didWrote reusable Ansible playbooks and Terraform modules against the bpg/proxmox provider, so a build is defined once and applied the same way every time. A repeatable build went from roughly 4 hours of manual work to about 17 minutes. The drift stopped because the declarative definition became the only route to a new host. This is what we provision with now.

Microsoft 365 Copilot Agent Suite

5 agents · no added licensing

Problem: Support tickets from Japan arrive in Japanese and most of our engineers do not read Japanese. Separately, the same few kinds of analysis and write-up were being redone by hand every time they came up.

What I didBuilt five agents in Copilot Studio and Agent Builder, each with its own instructions and scope: Japanese ticket analysis, Proxmox and DevOps operations support, root cause analysis and countermeasure documentation, web application planning, and supervisor support. Nobody asked for these. They went live in July 2026 on licensing the company already pays for, so there was no extra cost to approve.

How they are builtThe ticket agent produces technical English analysis aimed at engineers rather than a plain translation. It is grounded in an archive of past tickets that have human translations, and it does a knowledge base lookup before generating rather than after. All five share an instruction preamble I factored out that tells the agent to work from evidence and ask a clarifying question instead of guessing. Reusing one preamble also kept each agent inside Copilot's instruction length limit, which was the practical constraint.
