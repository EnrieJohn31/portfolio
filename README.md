# Enrie John Edem - Portfolio

Recruiter-focused static portfolio for infrastructure, platform, and DevOps engineering roles. The site is intentionally framework-free so it remains fast, portable, and easy to deploy.

## Main files

- `index.html` - complete portfolio markup, styles, and interactions
- `Enrie_John_Edem_Resume.pdf` - the résumé linked from the site's download buttons. **Authored externally**, not generated by `scripts/build_resume.ps1` (see below)
- `Enrie_John_Edem_Cover_Letter.pdf` - template cover letter with per-application placeholders; not linked from the site
- `og-image-v3.png` - recruiter-focused social sharing preview (1200x630, kept under ~150 KB). Source: `scripts/og_image_source.html`, rendered at exactly 1200x630 with headless Chrome. `og-image-v2.png` is the superseded card, retained only so previously-cached shares keep resolving
- `scripts/og_image_source.html` - editable source for the social preview
- `certificates/` - course certificates and awards used by the credential viewer
- `vercel.json` - clean URLs and security headers
- `robots.txt`, `sitemap.xml`, and `404.html` - search and routing support

## Résumé source

> **Warning:** `scripts/build_resume.ps1` ends by copying its output over `Enrie_John_Edem_Resume.pdf` in the repository root. The current root PDF was authored outside this repo and has a different visual design. Running the script will replace it. Back the file up first, or delete the final `Copy-Item` line, unless you intend to switch back to the script-generated design.

`scripts/resume_source.html` holds the résumé content and has been kept textually in sync with the current PDF, so the script no longer regenerates *stale* content, only differently *styled* content. On Windows with Microsoft Word installed:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_resume.ps1
```

The generated artifacts are written to `output/docx/` and `output/pdf/`.

## Deploy to Vercel

This is a static project, so no build command or output directory is required.

```powershell
npm install -g vercel
vercel --prod
```

When moving to a custom domain, update the canonical URL, Open Graph URLs, JSON-LD URL, `robots.txt`, and `sitemap.xml` together.

## Rebuilding the social preview

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu --hide-scrollbars --window-size=1200,630 --virtual-time-budget=8000 --screenshot="og-image-v3.png" "file:///$PWD/scripts/og_image_source.html"
```

The source pulls Space Grotesk and JetBrains Mono from Google Fonts, so the render needs network access. If the card's text changes, bump to `og-image-v4.png` and update both `og:image` and `twitter:image` rather than overwriting. LinkedIn and X cache previews by URL, and an overwritten file keeps serving the old card for days.

## Content maintenance

Keep the portfolio and résumé aligned on job titles, dates, infrastructure scope, and outcome metrics. Describe projected cost avoidance as projected, and add exact measurement baselines only when they are safe to disclose and can be defended in an interview.

Job titles are presented functional-title-first with the official HR title in parentheses (for example, "Infrastructure & Systems Engineer (official title: Senior Technical Support Analyst)"). This mirrors the PDF; both must change together. Note that the résumé's header banner reads "Infrastructure & Platform Engineer" (the broader positioning line) while the current role's functional title remains "Infrastructure & Systems Engineer". The site uses the same split: Platform in the `<title>`, meta, and JSON-LD `jobTitle`; Systems in the experience entry.

The provisioning metric appears in both `index.html` and `scripts/resume_source.html` and must be changed in both: `~4 hours` manual build-to-ready to `~17 minutes` automated (approximately 93%). It is stated with its basis on the page so it can be defended directly in an interview.

### The ₱8M migration figure

The ₱8M projected cost avoidance was previously kept off the site and was reintroduced in the 2026 résumé revision. It is presented on the site as **projected cost avoidance, not realized savings**, sourced to the cost model written for the Kaizen proposal, and the impact card's footnote states the scope explicitly.

The original objections still stand and should be rehearsed before any interview, because a sharp interviewer will raise them:

- VMware has licensed per physical core rather than per socket since the Broadcom acquisition, so a per-socket model overstates avoidance.
- A Proxmox subscription is itself a recurring per-socket cost and must be netted out of the gross figure.
- Operating-system and database licensing are unaffected by hypervisor choice; the site's footnote already excludes them.

If the underlying model cannot survive those three questions, reduce the claim rather than defend it.
